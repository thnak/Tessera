preview: paint real text through the production text stack, with the font as data

Issue #387. The canvas preview shipped no font, so every `Text` and `Button` painted its box
only and was counted in `text_skipped` -- "a preview whose buttons and labels have no text is
not a faithful preview", and the issue is right about that.

**Nothing was reimplemented.** `CountingSink::draw_text` incremented the counter and drew
nothing; it now forwards to the production `Batched2DSink`, which shapes with
`HarfBuzzShaper` and draws through `TextRenderer`'s bounded glyph atlas.
`PreviewTextStack` is a *lifetime* over those production pieces, mirroring
`app::detail::TextStack`, so the preview and the app cannot drift:

```
Counter.tsx, null backend     draws=1  vertices=24   text_skipped=3
                              draws=6  vertices=138  text_skipped=0  glyphs_dropped=0
```

**Two defects found by rendering rather than by reading:**

1. **Layout and paint would have disagreed.** `prepare_scene`, `layout_scene`,
   `PreviewSession::Options` and `CanvasSceneSession` used the *stub* measurer (a fixed 0.5
   em per code point), so a laid-out box could not match the ink drawn in it. All four now
   take the real measurer.
2. **Every `Button` was blank in a different way than expected**: a button's caption lives in
   `props["label"]`, not `node.text`, so `scene_build.cpp` painted an empty box even with a
   font present. Both captions paint now.

**The font is a page asset, not embedded in the Wasm.** IBM Plex Sans Regular, OFL-1.1 with
Reserved Font Name "Plex", subset to 372 glyphs (Latin-1 plus the samples' punctuation) at
38400 raw / 19534 gzip, shipped under `designer/web/public/fonts/` **with its `OFL.txt`
beside it**. The page fetches it same-origin and hands the bytes to
`tessera_canvas_set_font`; nothing leaves the browser. `THIRD_PARTY_NOTICES.md` and
`dependencies.md` record it as **design-time (`V1 design-time (studio)`)**, so it is correctly
*excluded* from the production license bundle and SBOM -- and both gates still pass
unchanged, which is the check that the classification is honest rather than convenient.

**Determinism proven on three Vulkan renders of the same bytes**: byte-identical, sha256
`d7bb1225...1d2f006`. The ctest also proves two independent null devices record identical
draw/vertex/text counts **and that a font-free frame differs** -- so the face really comes
from the bytes rather than from anything the host supplies. No system font, no fallback
chain, no clock, no locale.

**The atlas limit has defined, attributable behaviour.** The atlas is bounded
(`1024x1024, 2 pages, 1 oversample`) and never grown. When every page is full and nothing may
be evicted, `get_glyph` returns an unplaced entry that **still carries the advance**, so the
line box and every following glyph keep their positions and only that glyph's ink is absent.
It is counted in a new `glyphs_dropped` field, and the test proves it with a 32x32 one-page
atlas: `text_skipped == 0` while `glyphs_dropped > 0`. Dropping a glyph is visible and
counted; silently reflowing the line would have been worse.

**A real Wasm bug the probe caught:** `HEAPU8` was not exported, so the page had nowhere to
write the font bytes and would have failed in a real browser. Fixed by adding it to
`EXPORTED_RUNTIME_METHODS`, and the new `canvas-font` parity mode is wired into both
`webgpu.yml` and `pages.yml` so the next regression fails CI instead of a user's browser.

The budget was raised 470568 -> 492748 (+22180 = 19534 font + 1991 licence text) with the
reason in the note: a reviewed raise for a measured asset, not a loosened pin.

Verified: full build clean, `ctest --preset vs2026-release --parallel 12` -> 605 tests, 0
failed; `clang-format --dry-run -Werror` clean on all 21 touched files; `check_source_size.py`
0 errors; `check_public_api.py` 0 added, 0 removed; `gates.py` 11/11; the Emscripten build
succeeds for both Wasm modules; `npm ci`/`typecheck`/`build` clean; the three page suites and
the share round-trip pass; `scene_frame_parity` NATIVE REFERENCE OK.

**Not verified, stated plainly:** the pixel acceptance itself in a browser -- there is no
WebGPU device here, so the WebGPU render and the comparison against a lavapipe golden have
not run, and the browser-side paint is proven structurally (module loads, ABI works, refusal
paths answer) rather than visually. The Vulkan determinism evidence is an RTX 4060, which
proves the path works and is explicitly not a golden.
