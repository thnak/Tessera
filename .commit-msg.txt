custom hooks: typings, state carry and the last stale rejection claims (#647)

Three of #647's four items were already satisfied by the expansion pass; this
lands the fourth and the documentation the sweep missed.

**State carry.** The preview carries state across an edit by id, and an
expanded id is `<hook>_<n>__<name>`, so state survives an edit that keeps the
call order. That property was asserted in the spec and never tested. The new
`test_state_ids_are_stable_across_an_edit` pins both halves: an unrelated edit
keeps `useFlag_1__on` and `useFlag_2__on`, and a reorder changes them, which
is the honest limit of the rule — the preview cannot tell a reorder from a
different hook, so it must not carry state across one.

**Typings.** `jsx-subset-v1-jsx.md` section 16.2 now says an exported custom
hook gets a declaration generated from its declaration, not from the
expansion, because the expansion is per call site and the editor sees one
function.

**Generated member names** were already proven: the differential fixture "two
calls of one hook" compares the expanded IR against a hand-written component
with `on`/`on2` and `flip`/`flip2`.

**Three stale rejection claims** the earlier sweep missed, because they did
not use the words "custom hook" next to "rejected":

- `jsx-subset-v1.md` section 7.1 said "hooks written by app developers are
  rejected".
- `behavior-hooks.md` said "a hook declared in the project is rejected".
- `jsx-frontend.md` listed `TESSERA_REACT_CUSTOM_HOOK` as an unconditional
  diagnostic; it is now the switch-off path only.

`jsx-subset-v1.md` stays at 598 lines (the replacement is the same length).
