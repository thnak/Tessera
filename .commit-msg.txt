custom hooks: turn the expansion on by default (#645)

The expansion pass, its diagnostics and its eight differential fixtures
already landed behind `FrontEndOptions::custom_hooks`. This flips the
default, which is what #645 asks for: a project-declared `use...` function
is now expanded at each call site instead of rejected.

The switch stays so a caller can pin the old rejection, and the
`TESSERA_REACT_CUSTOM_HOOK` code stays in the registry for that path.

Flipping the default exposed four real defects, all fixed here:

- **The corpus measurement and the browser diagnostics path never ran the
  expansion.** Both called `parse_module` and `analyze_module` directly, so
  they measured a pipeline the compiler no longer has: a custom hook came
  out as `TESSERA_REACT_UNKNOWN_HOOK`. `tools/corpus/measure.cpp` and
  `tools/codegen/diagnose.cpp` now run the pass between the parse and the
  rules, exactly as the driver's `SourceFile` does, and the diagnose path
  reports the expansion's own diagnostics first.

- **The size limit underflowed.** `added = body.size() - before` is
  `SIZE_MAX` when the expansion SHRINKS the body, which it does for a hook
  whose body is only a `return`: the call statement is replaced by nothing.
  A hook that added no code at all was reported as adding 18 quintillion
  statements.

- **The destructuring rename allowance leaked into components.** The
  parser allowed `const {a: c} = b` whenever the switch was on, because the
  allowance was written for hook call sites (`const { page, next: goNext }
  = usePagination(...)`) and gated on the switch alone. It is now gated on
  the initializer being a custom-hook call, which is the only place the
  expansion consumes a rename.

- **`sample_compile` fails on the base commit too** (`style/parser.hpp`
  warns under `/WX`). That is pre-existing and unrelated; it is left alone
  rather than folded into this landing.

The corpus golden moves the way the change predicts: `custom-hook.tsx`
goes from `rejected ... pipeline=TESSERA_REACT_CUSTOM_HOOK` to
`accepted ... pipeline=ok`, and `TESSERA_REACT_CUSTOM_HOOK` disappears from
all three rejection tables. `corpus_measure_tests` gains `--write`, the
convention the codegen goldens already use, so the report is regenerated by
the code that measures it rather than by hand.

Evidence: `hook_expansion` (16 rules), `hook_expansion_differential` (8
fixtures), `jsx_module`, `jsx_diagnostics_registry`, `corpus_measure`.
Full suite: 731/732, the one failure pre-existing. Gates: 12/12.
