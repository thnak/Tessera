hook: useOverflow, the cut index from the last layout pass (#634)

`useOverflow(target, { reserved, gap })` reports how many leading children
of a row fit, and whether any do not. The engine owns the measurement:
`layout::LayoutReadModel` holds every node's box from the last pass, so the
behavior reads sizes rather than polling or forcing a layout.

That is the rule the issue asks for ("recomputes on size or content change
without a layout loop"): the behavior never asks for a layout, so a
component that renders `count` children settles in one pass, because the
widths it measures are the widths the previous pass already committed.

Two details that make the count usable:

- **The reserved slot is subtracted first.** An overflow list usually ends
  with a "more" button, which takes width the items cannot use, so the
  count is the number that fit *alongside* the button.
- **An unmeasured child stops the walk.** A child the last pass did not
  measure (added since) cannot be counted, because counting it would claim
  a width nobody measured.

With no read model at all the behavior reports `count = 0` and
`overflowing = true`: a component renders its narrow layout for the first
frame rather than claiming everything fits, the same rule
`size_class_for` applies to an unmeasured width.

`Services` gains the layout read model, which is the second time a behavior
has needed more than the router. The clipboard and overflow tests now use
designated initializers, so adding a service does not silently shift a
positional one.

Evidence: `overflow` (11 rules, including the reserved slot, the gap, and
the unmeasured-child stop), `hook_manifest` and `behavior_registry`. Spec:
`docs/specs/use-overflow-v1.md`.
