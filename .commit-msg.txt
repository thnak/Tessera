hook: useMediaQuery, one evaluator shared with the cascade (#631)

`useMediaQuery("(min-width: 600px)")` returns a reactive boolean for one
media query. The rule the issue states is "consistent with useBreakpoint
and the stylesheet's media evaluation (same engine path, no second
evaluator)", so the hook calls `style::parse_media_query_list` and
`style::evaluate` — the same two functions the cascade calls — and nothing
else. `media_query_match` proves the agreement directly: for every query
and width in its table, the hook's answer equals the cascade's, and a
query written at a size-class threshold matches exactly when the class is
on the corresponding side of it.

This is the first `environment` hook that takes an argument, which the
path did not support: it assumed zero parameters and a string return. The
manifest now declares a `value` parameter, the analyzer derives its arity
from the manifest rather than a name check, the IR carries the argument,
and codegen emits a `bool` field, one parsed matcher, and a
`set_environment_<name>_context(const style::MediaContext&)` the host
calls with the same context the cascade resolves against. A media query
registers no string consumer, because it is not pushed as a value: the
component evaluates its own parsed query.

A malformed query is `false` rather than an error: a media query is a
string a component may build at runtime, and a bad one must not take the
frame down. An unevaluated query is also `false`, so a component renders
its non-matching layout for the first frame rather than claiming a match
it has not checked.

Evidence: `media_query_match` (8 rules, including the cascade agreement
and the size-class agreement), `codegen_environment` (the generated
surface) and `hook_manifest` (the entry's shape). Spec:
`docs/specs/use-media-query-v1.md`.
