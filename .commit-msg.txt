hook: useClipboard, copy with a self-clearing feedback window (#632)

`useClipboard({ text })` copies text through the platform seam and reports
`copied`/`failed`. The engine owns the mechanism (`hal::Clipboard`, with
`MemoryClipboard` as the deterministic test implementation); this lands the
hook's half.

The hook takes no target ref, because the clipboard belongs to the window.
The behavior holds the seam rather than the component, because a component
that reached the HAL directly would need a platform handle in generated
code, which ADR-020 forbids.

The feedback window is a deadline, not a timer: the behavior reads the time
from `Services::now_s` and compares it in a new `Behavior::tick`, so a
`ManualClock` test advances it explicitly and no thread or timer exists.
`tick` is a defaulted virtual on the seam, so the five behaviors that have
no deadline pay nothing.

Two rules worth naming:

- **Empty text copies nothing.** A copy button whose text is empty (a code
  block that failed to load) must not wipe the clipboard the user was
  carrying. That is a data-safety rule, not a nicety.
- **A failure's feedback expires too.** A "Copy failed" label that stayed on
  screen forever is as wrong as a "Copied" one.

`Services` gains the clipboard and the clock, which is the first time a
behavior has needed anything beyond the router. Both are nullable, and a
build with neither reports `failed` rather than crashing.

Evidence: `clipboard_copy` (11 rules, including the expiry, the empty-text
guard and the no-seam path), `hook_manifest` and `behavior_registry`. Spec:
`docs/specs/use-clipboard-v1.md`.
