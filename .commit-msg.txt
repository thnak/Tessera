hook: useScrollLock, reference-counted so nested layers do not unlock each other (#633)

`useScrollLock(target, { active })` stops the background from scrolling
while a modal layer is open. The engine owns the mechanism: a node with its
scroll axes clear is not a scroll container, so `scroll_target` skips it and
a wheel or gesture chains past it. This lands the hook's half.

The interesting part is the reference count. Two dialogs can be open at
once (a confirmation over a settings sheet), and the inner one closing must
not unlock the page the outer one still needs locked. A count per behavior
cannot see the other behavior, so the count lives in one bounded table keyed
by the node: a fixed array of `{node, count, axes}` records, allocation-free
on the lock path. A behavior that cannot get a slot leaves the node unlocked
and reports `locked = false` rather than claiming a lock it does not hold.

The table also records the axes the node had before the first lock, so the
last release restores exactly what was there. Restoring both axes would make
a horizontally-clipped page suddenly scroll sideways.

`locked` reports this behavior's reference, not whether the node is locked
overall: a nested layer that releases its own lock while an outer one still
holds one reports `false` and the page stays locked, which is the truth a
component needs.

The destructor releases the reference, so a behavior destroyed without an
explicit detach cannot leave a page unscrollable for the session.

Evidence: `scroll_lock` (11 rules, including the nested reference count and
the axis restore), `hook_manifest` and `behavior_registry`. Spec:
`docs/specs/use-scroll-lock-v1.md`.
