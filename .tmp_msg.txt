feat(css): scan and scope a CSS module file (#463 slice 2b)

The rewrite is the whole point of CSS-module isolation, so it is its own
library with its own tests rather than a helper inside lowering.

`scan_module_css(path, text)` returns the path hash, the class and keyframes
tables, and the rewritten text. It renames only `.class` selectors, `@keyframes`
names, and the `animation-name`/`animation` references to a keyframes declared
in the same file. Ids, attributes, type selectors, `::part()`, custom
properties, `@font-face` families and `@layer` names are never renamed, and a
`.` inside a declaration value is not a selector.

The rewrite is byte-preserving: the output differs from the input only at the
renamed spans, so comments, odd whitespace and formatting survive. A test
proves it by stripping the inserted suffixes and comparing to the input.

The tokenizer is split into its own `tessera_css_tokenizer` target. It was
already scene-free, so the compiler can tokenize a module file without linking
the scene graph, the cascade or the rest of the style engine. The headers stay
where they are, so the public API baseline does not move.

Two error-precedence choices the spec left open: `:global(` is validated up
front so a malformed one reports MALFORMED_GLOBAL rather than the generic brace
error, and `:global { }` is reported from the selector rewriter. `-webkit-`
keyframes and animation properties are treated as aliases of the unprefixed
forms, because renaming only the unprefixed form would leave a real reference
unscoped.

The hash is the low 24 bits of FNV-1a 64 over the project-relative POSIX path,
pinned by four independently computed test vectors.
