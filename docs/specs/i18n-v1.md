# Internationalization v1

Status: proposed (Big Step F, defined in [AGENTS.md](../../AGENTS.md#big-steps-group-work-dont-micro-step), section "Big Steps").
Decision: [ADR-030](../../decisions/ADR-030-app-platform-completeness.md) (app-platform
completeness: navigation, restore, shell, i18n, accessibility, data). Companion to
[`services.md`](../design/services.md), [`text.md`](../design/text.md),
[`responsive.md`](../design/responsive.md), and [`accessibility-v1.md`](accessibility-v1.md).

i18n (internationalization: locale, message, format, and text-direction handling) is runtime
behavior, not a string table bolted on at the end.

Acronyms used here: ICU = International Components for Unicode (the library for message
formatting, bidi, and segmentation); CLDR = Unicode Common Locale Data Repository (the locale
data ICU uses); BCP-47 = the IETF language-tag format (for example `en-US`); RTL =
right-to-left; bidi = bidirectional text algorithm. The text stack is described in
[`text.md`](../design/text.md).

## 1. Locale negotiation

- Inputs: OS locale(s), app default, user override, per-window override.
- Resolve to a supported locale (language/script/region) with a documented fallback chain.
- Locale is a runtime input to styles, layout direction, formatting, and text.
- Changing locale reflows/re-renders; it does not restart the app unless the platform forces it.
- Deterministic mode pins locale/ICU data; no system locale leakage in goldens.
- Unsupported locale -> default locale + diagnostic, never empty strings.

## 2. Catalogs and keys

```json
{
  "locale": "en-US",
  "messages": {
    "orders.title": "Orders",
    "orders.count": "{count, plural, one {# order} other {# orders}}",
    "errors.required": "Required"
  }
}
```

- Stable message ids; no sentence concatenation.
- ICU MessageFormat for plural/select/number/date.
- Missing key -> default locale + visible key/diagnostic in dev; never crash.
- Catalog versions/hashes are packaged; no network fetch at runtime unless explicit.
- Fallback chain is deterministic; regional variants inherit base language.
- No user data embedded in keys; parameters are typed/escaped.

## 3. Formatting

- Numbers, currency, percent, units, dates/times, relative time, lists, measurement.
- ICU/CLDR data is pinned/embedded; time zone comes from the platform but is explicit.
- 12/24h, first day of week, calendar system, and numbering system follow locale.
- Formatting is pure/cacheable by `(value, style, locale, timezone)`.
- Do not hand-format dates/numbers in components; use the service.

## 4. Text, RTL, and fonts

- Direction is per paragraph/run from bidi; `start`/`end` are logical.
- The layout direction of a styled subtree is the inherited `direction` property, which the locale's
  base direction seeds. Styling uses the inline-axis logical properties
  (`margin-inline-*`, `padding-inline-*`, `inset-inline-*`, `border-inline-*`, `text-align:
  start/end`), so one stylesheet mirrors between LTR and RTL; physical `left`/`right` stay physical
  and are only used when the geometry is genuinely not direction-dependent
  ([`stylesheet-v1.md`](stylesheet-v1.md) section 11.1).
- RTL mirrors layout/icons only for direction-dependent elements; see "RTL/icon policy" in
  section 8.1.
- Scroll and overscroll mirroring (wheel/pointer offset direction, scrollbars, overscroll effects)
  is **not** in V1: scroll offsets stay physical in both directions until that lands, so a
  stylesheet must not assume a mirrored scroll axis. See
  [`scroll-and-gestures-v1.md`](scroll-and-gestures-v1.md).
- Font fallback follows the text stack; locale may add preferred font families.
- Text expansion (German/Finnish) must not clip; layouts use intrinsic/wrap rules.
- Pseudo-localization (accented/expanded) is a test mode.
- Line breaking/segmentation uses ICU; no ASCII assumptions.

## 5. Runtime changes

- Locale change triggers style/layout/text invalidation and formatting cache invalidation.
- Route/screen state is preserved on locale change (no rule is specified for state that
  cannot be preserved); unsaved text is not lost.
- Number/date inputs reparse according to locale; ambiguous input is rejected.
- Accessibility announcements use the new locale.
- Per-window locale override is explicit; app-global default otherwise.

## 6. Build and packaging

- Catalogs are compiled/validated at build time (ICU message syntax).
- Unused/missing/duplicate keys fail CI; pseudo-locale catalog is generated for tests.
- Only needed locales are packaged; locale packs are versioned with the app.
- Catalog format/version is documented; migrations are explicit.
- Licenses for CLDR/ICU data are shipped (see [`dependencies.md`](dependencies.md)).

## 7. Testing

- Plural categories (zero/one/two/few/many/other), gender/select, nesting.
- Dates/numbers/currency/relative time/time zones; DST boundaries.
- RTL/bidi layout, mixed scripts, text expansion, font fallback.
- LTR/RTL mirrored layout: one stylesheet laid out under both `direction` values produces mirrored
  boxes (stylesheet-v1.md section 11.1); scroll mirroring is out of scope until it lands.
- Missing keys/fallback chain/pseudo-localization.
- Runtime locale switch and state preservation.
- Headless/golden with pinned locale/fonts/ICU.

## 8. Security and privacy

- Catalogs are trusted build artifacts; runtime catalogs are validated/allowlisted.
- Escape/parameterize messages; no HTML/JS interpolation.
- Do not log personal data embedded in messages.
- Locale/region is not authentication; permissions/roles are separate.

## 8.1 Detail design

Ownership:

| Component | Owns | Does not own |
|---|---|---|
| `LocaleResolver` | requested/supported/fallback locale, direction | Text shaping |
| `MessageCatalog` | compiled message ids/patterns | UI layout |
| `Formatter` | number/date/currency/list/relative time | Business formatting rules |
| `ui/text` | shaping/bidi/line breaking | Message selection |
| `services` (see [`services.md`](../design/services.md)) | locale change event, settings | Catalog build |

V1 catalog format (decided in Q-15, see the gap-closure decisions below and
[`app-completeness-gap-resolutions-v1.md`](../architecture/app-completeness-gap-resolutions-v1.md)):

- Source: JSON with ICU MessageFormat strings, one file per locale, stable message ids.
- Build: parse/validate ICU syntax -> check missing/duplicate/unused ids -> compile to a
  generated C++ table (id enum + pattern data) or a compact binary catalog.
- Runtime: no source parsing, no network catalog fetch; fallback is compiled in.
- `en-XA` pseudo-locale is generated by the build for expansion/RTL tests.

Resolution:

```text
requested (user/window/OS) -> normalize (BCP-47) -> exact match
  -> language+script -> language -> fallback_locale -> default_locale
```

- Direction is per paragraph/run from bidi; locale supplies the base direction hint.
- Locale change increments `locale_epoch` and invalidates: text shapes, formatting caches,
  layout, accessibility announcements, date/number parsers.
- Per-window override is explicit; app-global default otherwise.

Formatting cache key: `(value, style, locale, timezone, numbering_system, calendar)`. Cache is
bounded and cleared on locale/timezone change.

Build/package:

- ICU data can be a reduced/static data build; pin version in `dependencies`/SBOM (software
  bill of materials).
- Catalogs are versioned with the app; missing locale pack falls back rather than failing launch.
- Every catalog key must exist in the default locale; unused keys fail CI (same rule as
  section 6).

RTL/icon policy:

- Directional icons (arrows/back/next) mirror in RTL; logos, clocks, media controls, and
  brand marks do not unless the icon declares `mirror`.
- Layout uses logical start/end (`direction` plus the logical properties of
  [`stylesheet-v1.md`](stylesheet-v1.md) section 11.1, mapped to Yoga's Start/End edges); physical
  left/right only when semantically required. Mixed LTR/RTL stylesheets are tested by laying out the
  same sheet under both directions and asserting mirrored boxes.
- The resolved base direction (`LocaleResolution.right_to_left`) supplies the root `direction`;
  pseudo-locales therefore exercise the same contract: `ar-XB` resolves through its kept ancestor
  `ar` and is right-to-left. The in-tree layout test asserts the mirrored rectangles directly
  because the reduced-ICU locale pack that generates `ar-XB` is not part of the default test build.
- Scroll and overscroll mirroring is Later (see section 4); the resolved direction does not flip
  scroll offsets in V1.
- Mixed-direction text keeps numbers/URLs/code runs isolated; no manual bidi control characters
  in messages.

Failure/edge cases:

- Malformed message -> build error; runtime fallback shows key + diagnostic in dev.
- Unsupported locale -> default + diagnostic; never empty text.
- Missing plural category -> `other` fallback; no crash.
- Invalid/ambiguous date/number input -> reject with a field error; never guess silently.
- Time zone/DST changes -> formatter cache invalidated; displayed times update at the next simulation tick (one fixed-step update; see
  [`game-loop.md`](../design/game-loop.md)).

Gap-closure decisions:

Gap IDs (`G-16`, `G-17`) and question IDs (`Q-15`, `Q-16`) refer to
[`app-completeness-cross-check-v1.md`](../architecture/app-completeness-cross-check-v1.md) and
their resolutions in
[`app-completeness-gap-resolutions-v1.md`](../architecture/app-completeness-gap-resolutions-v1.md).

- **G-16/Q-15**: source catalogs are JSON + ICU MessageFormat, compiled to a generated C++
  table/binary; ICU data is static/reduced and pinned; locale packs are bundled (no runtime
  source/network); missing locale falls back. FTL (Fluent, a message format) and runtime language packs are not in V1.
- **G-17/Q-16**: pseudo-locales `en-XA` (expansion) and `ar-XB` (RTL) are build-generated.
  Icons declare `mirror:auto|never`; directional icons mirror, logos never. Per-window locale
  override is allowed with app-global default.

## 9. Deferred/open questions

V1 is the first-release scope ([AGENTS.md](../../AGENTS.md#non-negotiables) rule 8). Items below have no decision yet.

- Locale-aware collation/sorting and search.
- Runtime language packs (after V1).
- Translation workflow/TMS (translation management system) integration.
- Font fallback policy per script beyond "missing glyph is a diagnostic".
